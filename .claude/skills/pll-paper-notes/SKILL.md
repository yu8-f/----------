# PLL論文 読書ノートサイトへの追加

`PLL論文/読書ノート/` は長田将さんの博士論文の読書ノートから始まった、Netlifyでホストしている
個人用のHTML読書ノート集(URL: `osada-hakuron.netlify.app`、ドメイン名は変更しない方針で合意済み)。
新しい論文を読んだときは、別サイトを作らずここに統合する。

## サイトの現状構成

- `index.html` — 全体の目次。論文ごとにセクション(見出し+カード)で分かれている。
- `basics.html` / `thesis-notes.html` / `ch2-3-notes.html` — 長田博論のノート(3点セット)。
  **これらのファイル名・中身は触らない**。新しい論文が来ても長田博論のノートは無関係。
- `dtc-hm-optimization-notes.html` のような、論文ごとの単独HTMLファイルが並ぶ。
- `figures/` — 長田博論の図は直下に `fig_<章>_<番号>.png` で置かれている。**新しい論文の図は
  `figures/<論文名の略称>/` のようにサブフォルダを切る**こと。命名規則が違う図を同じ階層に
  混ぜるとファイル名が衝突しうるため。

## 手順

### 1. PDFを読んで中身を理解する

`~/.claude/skills/paper-digest` と同じ型で理解する:
一行で何をした論文か／要点(手法・主な結果・限界)／マスターの卒論(HMベース・Dual-Feedback
構成、低雑音・広チューニングレンジPLL、飯塚研)との関係／深掘り価値がある箇所・飛ばしていい
箇所／用語補足。ただし **保存先は vault ではなくこのリポジトリの読書ノートサイト** という点が
paper-digest と違う(このリポジトリのPDFはリポジトリ内で完結させる方針)。

PDFの読み方:
- ページ数が少なければ `Read` ツールでそのまま読める。
- `pdftoppm is not installed` のエラーが出たら、`pdftotext -layout <pdf> <出力.txt>` で
  レイアウト保持のままテキスト化してから `Read` で読む(Windows環境でも Git Bash に
  `pdftotext.exe` が入っていることが多い)。

論文の位置づけ(長田博論そのものの先行研究か、飯塚研の姉妹研究か、外部の関連研究か)は、
著者リストに Osada や Iizuka が入っているかで見分けがつく。姉妹研究であれば「先行研究」
というより「関連研究・比較対象」として扱い、卒論との関係を厚めに書く。

### 2. 図が必要なら切り出す

`scripts/crop_pdf_figs.py` に雛形がある。PyMuPDF(`fitz`)を使うので poppler(pdftoppm)が
無い環境でも動く。流れ:

1. スクリプトの `pdf` と `out_dir` を書き換え、`crops` を空のまま実行 → 全ページが
   `pages/page_NN.png` に画像化される。
2. 欲しい図が写っているページを `Read` で目視し、だいたいの位置(ページ番号、左右どちらの
   カラムか、上下どのあたりか)を当たりをつける。
3. `crops` 辞書に `"名前": (0始まりページ番号, x0, y0, x1, y1)` をポイント単位
   (レターサイズなら 612×792)で追記して再実行。
4. 切り出した画像を `Read` で確認し、上下左右が欠けていたら座標を1回で完璧に当てようと
   せず、5〜10ポイント刻みで広げて再実行する方が早い。
5. 満足いく図が揃ったら `読書ノート/figures/<論文名>/` にコピーする。

主要な図(結論を示すグラフ、提案アーキテクチャのブロック図)を3〜7枚程度選べば十分。
表や参考文献、著者紹介ページの図まで律儀に全部切り出す必要はない。

### 3. 新規HTMLノートを書く

既存の `basics.html` を開いて、`<style>` の中身(CSS変数定義、`.sidebar` / `.card` /
`.callout` などのクラス)をそのままコピーして使う。デザインを再発明しない。骨格:

- サイドバー: タイトル、出典の一行、`← 目次にもどる`(index.htmlへのリンク)、
  セクションへのアンカーリンク一覧。
- ページヘッダー: 論文の正式タイトル・著者・誌名巻号年・出典。
- 本文セクション(`<section class="sec">`)の目安構成:
  0. この論文を超ざっくり
  1. 背景・提案手法の要点(図があればここで埋め込む)
  2. 結果の要点(図があればここで埋め込む)
  3. マスターの卒論との関係(厚めに)
  4. 深掘り価値がある箇所 / 飛ばしていい箇所
  5. 用語・前提の補足

厳密にこの節構成に従う必要はなく、論文の構造に合わせて増減してよい。図は
`<div class="fig"><img src="figures/<論文名>/<ファイル名>.png" alt="..."><figcaption>...</figcaption></div>`
の形で埋め込む。

ファイル名は英語で内容がわかる短いkebab-case(例: `dtc-hm-optimization-notes.html`)。

### 4. index.html を更新する

- まだ「論文ごとのセクション分け」になっていなければ、`<h1>` とリード文を特定の1論文専用の
  文言から一般化し、既存の3枚を「①長田博論」セクション、新規ノートを「②関連論文」セクション
  のように分ける。
- 既にセクション分けされていれば、該当セクションに新しいカード(`<a class="card">`)を
  1枚追記するだけでよい。
- 既存の3カード(basics/thesis-notes/ch2-3)の文言は変えない。

### 5. README.md を更新する

`PLL論文/README.md` の `読書ノート/` の説明に、追加したファイルと図の置き場所を反映する。

### 6. 見た目を確認する

Browser paneで `file:///.../読書ノート/<ファイル名>.html` を開いて崩れがないか見る。
**注意**: このリポジトリのファイルは Browser pane 上で「プロジェクト外ファイルの
static snapshot」扱いになり、`<img>` の相対パス画像が表示されないことがある。これは
`thesis-notes.html` など既存ノートでも同じ挙動になる既知の制約で、バグではない。切り分けの
ため、迷ったら既存ノートの画像も同じように表示されないか比較する。実際のローカルブラウザ
(Chrome等)やNetlifyデプロイ後は問題なく表示される。

### 7. コミット・push

このリポジトリは owner の指示で直接 main にコミットしてよい方針(このリポジトリの
CLAUDE.md「Git workflow」節を参照)。コミットメッセージは日本語、末尾に `Co-Authored-By:` 行を付ける。
ただし **push して良いかは毎回一言確認する** (Netlifyの自動デプロイが走るため、
「コミットまでは自動でいいがpushは確認してほしい」という空気がある場合は特に)。

## やらないこと

- vault(`claude_connect/papers/`)へのノート化はしない。このリポジトリのPDFは
  リポジトリ内(読書ノートサイト)で完結させる。
- 既存の長田博論3ファイル(basics/thesis-notes/ch2-3)のファイル名・中身の変更。
- Netlifyのドメイン名変更やサイトの作り直し(1サイトに統合する方針が合意済み)。
